### [# 后端架构 AI Friendly 的标准与路径：面向无人值守开发时代的系统重构](https://mp.weixin.qq.com/s/XpSpAiWY-nXjw8d8QPbabg)
#五星收藏 

真正的 AI Friendly，应该是让一个 AI Agent 能够在有限上下文、有限权限、有限试错成本的前提下，正确理解系统、定位边界、拆解任务、修改代码、验证结果、评估风险、生成变更说明，并在自动化规则约束下安全地推进系统演进。
==换句话说，过去我们建设的是「可维护系统」，未来要建设的是「可被智能体维护的系统」。==

AI Friendly系统几项基本原则：
1. 第一原则：架构事实清晰。==系统知识需要从“人脑资产”变成“机器可读资产”==。
	![[Pasted image 20260616102255.png]]
2. 第二原则：完整的架构地图。==先让AI看懂整个，而不是某个服务。== 完善的架构地图，至少要能回答以下问题：
	1. 系统有哪些业务域
	2. 服务如何分层
	3. 核心链路如何流转
	4. 服务之间的调用拓扑是什么
	5. 消息拓扑是什么
	6. 数据所有权如何划分
	7. 强弱依赖如何定义
	8. 系统的发布边界和故障隔离边界在哪里
	9. 历史遗留和未来演进方向是什么
		![[Pasted image 20260616104735.png]]
3. 第三原则：System Card 服务身份证：==从 README 到 System Card：每个微服务都需要一张“服务身份证”==。一张合格的Service Card应该包括以下内容：
	1. 服务定位
	2. 核心职责
	3. 核心实体
	4. 数据所有权
	5. 接口清单
	6. 消息清单
	7. 依赖清单
	8. 运行特征
	9. 变更约束
	10. 测试入口
	11. 发布与回滚
		![[Pasted image 20260616105708.png]]
4. 第四原则：Domain Clarity 领域模型要显式化。==让AI知道什么是“不能破坏的不变量”==。核心要点：
	1. 不变量
	2. 状态机
	3. 幂等与一致性策略
	4. 风险等级
		![[Pasted image 20260616110310.png]]
5. 第五原则：Skill-based：==把团队经验封装成AI可调用的工程能力==。
	1. ![[Pasted image 20260616111016.png]]
6. 第六原则：Harness Augmentation：==为AI Agent建立安全的执行轨道==。
	1. ![[Pasted image 20260616111248.png]]
7. 第七原则：Test-Gated AI Development：==测试体系从“防人出错”升级为“约束和指导 AI 行为”，不再只是守门员，而是红绿灯、每一个checkpoint 的“守门人”==。核心要包含以下工程约束：
	1. 单元测试
	2. 契约测试
	3. 集成测试
	4. 回归用例库
	5. 数据迁移测试
	6. 性能测试
	7. 架构验证：AI时代大型分布式系统需要特别关注
8. 第八原则：AI-Observable Architecture：==可观测性要变成AI的眼睛==。无人值守开发不只包括写代码，还包括排障、修复、优化和自愈。结构化可观测性指标如下：
	1. 日志要有统一格式
	2. 错误码要有语义
	3. Trace要能关联业务实体
	4. 告警要有Runbook
		![[Pasted image 20260616112602.png]]
9. 第九原则：Tiered Access Control 权限分级策略：==数据和权限：AI Friendly 不能以牺牲安全为代价==。两条核心原则：
	1. 分级权限模型：AI Friendly 不是把权限全部给 AI，而是让 AI 在不同风险场景下获得刚好足够的权限。
	2. 数据安全
10. 第十原则：Code Navigation Framework：==代码结构要可导航：让 AI 少猜路径==。
11. 第十一原则：Docs/Architecture as Code
	1. 文档即代码：文档必须参与 CI
	2. 架构即代码：Architecture as Code
12. 从 Copilot 到 Coworker，再到 Operator。后端系统 AI Friendly 的建设，不是一蹴而就一下子建设完成的，可以分三个阶段：
	1. 第一阶段是 Copilot
	2. 第二阶段是 Coworker
	3. 第三阶段是 Operator
